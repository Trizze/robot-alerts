# Switch the hosted service to its own Twitch app

Only the owner runs this procedure. Codex must not run the interactive helper or inspect its private inputs/output environment. No packages are needed beyond the existing Python, Node/Docker and SSH setup.

1. Sign in as **trizze** at https://dev.twitch.tv/console/apps. Open Applications → Register Your Application. Twitch requires verified email and 2FA.
2. Name: **Robot Alerts**. Category: **Website Integration**. Client type: **Confidential**, if offered. Add the exact redirect `https://trizze.tv/robot/api/auth/callback`, then Create.
3. Open Manage on the new application. Keep this page open for its Client ID. Click New Secret to create the new application's secret. Do not change the Marvin-Trizze app or its secret; other projects may use it.
4. In the owner's SSH terminal on marvin:

   ```sh
   cd /home/marvin/robot-alerts
   universe-admin 1
   npm run setup:hosted-app
   ```

5. Read the notice, type `SWITCH`, then paste Client ID and Client Secret at the two hidden prompts. No characters appear. Press Enter after each. Keep the terminal open until completion. No values belong in chat, command arguments or screenshots.
6. After success, open https://trizze.tv/robot/start/ and reconnect **trizze**. Connect **itsTrizze** in a separate browser profile/private window. Back in Trizze's dashboard https://trizze.tv/robot/dashboard/, choose Connect TrizzeBot and authorize **TrizzeBot**. The application name should now be Robot Alerts.
7. Refresh the existing OBS browser source and use Send test to OBS. Source URLs do not change. No real paid event or test points are generated by setup.

The helper prompts locally and sends credentials privately through encrypted stdin to the existing `universe` host. It validates them using Twitch's token endpoint with an eight-second timeout and rejects redirects. It updates only the root-owned mode-0600 Robot Alerts env file, preserving all other values and both existing data/pattern keys. A fresh random webhook secret rejects old-app notifications after the switch; old app connections for unrelated projects are not revoked.

The existing container is stopped during maintenance. Streamer credentials become encrypted empty records marked disconnected; bot authorization, old sessions and pending unlock notices are cleared. Channel rows, points ledger, viewers, patterns, seen markers, appearance, anonymous totals and settings are retained. The service is recreated from the same image ID with loopback 8100, 192 MiB, 0.5 CPU and existing log limits. The previous stopped container is retained with a timestamp.

If validation fails, nothing changes. If startup fails, the helper attempts to restore the prior env in memory and restart the prior container; accounts may still need reauthorization if auth maintenance already completed. It never restores an older points database. Do not manually start a retained container with outdated env after a successful switch. Report only the fixed error/success message; never send env contents, credentials or raw Docker logs.

Reference: [Twitch app registration](https://dev.twitch.tv/docs/authentication/register-app/) and [token validation](https://dev.twitch.tv/docs/authentication/validate-tokens/) explain application-specific credentials and authorizations.
